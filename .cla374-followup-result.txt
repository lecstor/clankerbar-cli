### New findings, confined to the regression surface

**[WARN] internal/harness/claude.go:140 - `cmd.Cancel` is assigned after `cmd.Start()` (line 114): data race with os/exec's watchdog, and the group kill can be silently skipped.**
`Start` launches `go c.watchCtx(resultc)` at exec.go:783 whenever `Cancel != nil || WaitDelay != 0` - and `CommandContext` has already set a default `Cancel` (exec.go:490), so the goroutine *is* running by the time claude.go:140 overwrites the field. `watchCtx` reads `c.Cancel` at exec.go:804 with no happens-before edge to that write. Verified by reproduction (`/tmp/cancelrace`, os/exec 1.26): `WARNING: DATA RACE ... Read at ... os/exec.(*Cmd).watchCtx() exec.go:804 / Previous write at ... (assignment after Start)`. Functional consequence when the caller's ctx is cancelled inside the Start-to-line-140 window: the watchdog may run the *old* default `Cancel`, killing the direct child only - exactly the bug finding 2 was fixed to close. The window is only two cheap statements wide (lines 122-123) and the ceiling-kill path is safe (the `cancel()` in `consume` gives close(done)->receive ordering), which is why the suite is green; opencode is unaffected because it assigns before `Run`. **Fix:** move the `cmd.Cancel = func() error {...}` block (and its comment) to just after `setupProcessGroup(cmd)` / before `cmd.Start()`, mirroring opencode.go:307. The closure only dereferences `cmd.Process` at call time, so nothing else has to move.

**[WARN] internal/harness/opencode.go:292-294 with wallclock_test.go:227-250 - `cmd.WaitDelay` is now pinned by no test, while the rewritten comments promote it to a load-bearing backstop.**
Verified by mutation in `/tmp/cla374`: replacing `cmd.WaitDelay = 5 * time.Second` with a no-op leaves `TestOpencodeWallClockKillDoesNotHangOnAGrandchildHoldingTheStream`, `TestOpencodeProcessGroupKillTerminatesAGrandchild`, `TestOpencodeInvokeEndsASessionThatOutlivesItsWallClockCap` and `TestOpencodeCallerCancellationIsNotAWallClockCap` **all passing**. The reason is structural: the hang test's stub backgrounds `sleep 30 &`, which is *in* the process group, so the group kill now reaps it and Wait returns regardless of WaitDelay. This is not a defect introduced by the fix diff - it is a consequence of the group kill added in e171655 - but the fix diff is what re-labels WaitDelay "the backstop BEHIND that kill" for setsid escapees, so the comments now assert a property no test holds, and a future refactor deleting WaitDelay would go green. **Fix:** either add a stub that daemonises (`setsid sh -c 'sleep 30' &`, skipped where `setsid` is absent) so the escapee path is pinned, or say plainly in wallclock_test.go:222-226 that WaitDelay's escapee case is untested and this test now exercises the group kill.

**[NIT] internal/harness/opencode.go:302-303 - "never after Run has reaped the leader" is an overclaim.**
`Wait` reaps at exec.go:930 and only then receives from `c.ctxResult` (exec.go:937-938). `watchCtx` is sitting in a `select` between that send and `<-c.ctx.Done()`; if the context is cancelled in the microseconds around the exit, Go may pick the `Done` branch and call `Cancel` after the pid has been released. `os.Process.Kill` is safe there (it returns `ErrProcessDone` off the internal done flag), but `killProcessGroup`'s raw `syscall.Kill(-pid, SIGKILL)` has no such protection, so the pid-recycle hazard is narrowed by orders of magnitude rather than eliminated. **Fix:** soften to "only while os/exec still considers the process live - the post-reap window shrinks to the instant between Process.Wait and the watchdog handshake, versus firing on every capped session before". No code change warranted.

**[NIT] internal/harness/wallclock_test.go:224-225 - garbled sentence inverts the meaning.** "daemonised with setsid lands in a group of our signals' reach" is missing the negation; the same idea is stated correctly at opencode.go:285-286 ("a group of its own that no signal of ours reaches"). **Fix:** "lands in a group of its own, out of our signals' reach".

**[NIT] internal/harness/processgroup_test.go:156-171 - two small things in the new helper.** (a) The `elapsed` third return is discarded at both call sites (lines 68, 112), so `invokeOutcome.elapsed` and the whole third result are dead weight; drop them or assert on elapsed. (b) `(Result, error, time.Duration)` puts `error` in the middle, against Go convention - cosmetic only, the repo runs no linter (ci.yml:122 documents golangci-lint being left out deliberately). Also worth knowing, not worth changing: on the timeout path the Invoke goroutine and its stub subtree keep running while `t.TempDir`/`t.Setenv` cleanup unwinds - failure path only.

**[NIT] internal/harness/claude.go:139 - "filed separately" names no task.** Same at opencode.go:284 and wallclock_test.go:222. Everything else in these files carries a CLA ref. **Fix:** cite the follow-up ref once it exists, so the known gap is traceable from the code.
